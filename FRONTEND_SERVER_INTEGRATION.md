## Main integration fixes

- Normalized API errors, token refresh and `FormData` handling.
- Corrected server/frontend role mapping: CUSTOMER / STAFF / KITCHEN / RIDER / ADMIN.
- Corrected order lifecycle so Admin confirms to `CONFIRMED`, then Kitchen uses `/api/kitchen/:id/prepare` and `/ready`.
- Kitchen no longer calls inventory/product-admin endpoints that the KITCHEN role is forbidden to use.
- Rider dashboard now uses `/api/delivery/rider/...` endpoints instead of the general order status endpoint.

- Corrected coupon types to `PERCENT` / `FIXED`.
- Corrected user list response mapping and role update values.
- Checkout totals now mirror the server's default fee logic: ฿35 below ฿300, otherwise free (overridable with Vite env vars).
- Vite dev port changed to `5173` to match the server's configured CORS client origin.
- Customer order history now reads Delivery tracking from the server when a delivery record exists.

## Existing server limitations handled on the frontend

These were **not changed on the server**:

1. The server has no endpoint for a cashier to mark a CASH payment as `PAID`. The cashier UI is therefore read-only for payment state instead of sending unsupported fields.
2. The server exposes Stripe PaymentIntent creation but this frontend project does not contain a Stripe client confirmation flow. Checkout currently exposes the functional CASH/COD flow only.
3. The server has no Hero-slide API. The unsupported Admin Hero menu was removed from navigation.
4. The Admin user-role endpoint does not accept `RIDER`. Existing Rider accounts are displayed, but the frontend does not send an unsupported RIDER role update.
5. Product/category slugs are generated by the server using `[a-z0-9-]` only. New names must contain at least one Latin letter or digit to avoid an empty slug.
6. Coupon listing is Admin-only on the server. Public Home marketing therefore retains its static fallback content; coupon validation during checkout uses the authenticated validation endpoint.
7. The server computes its configured delivery/service fee for every order type. The checkout preview mirrors that behavior so the displayed total matches the server total.
